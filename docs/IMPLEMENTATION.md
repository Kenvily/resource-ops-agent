## 2. 数据身份与指标口径

集群键为`yz/zw`，源端origin通过环境变量配置；Grafana是展示入口，实际采集调用Prometheus HTTP API。只接受固定来源和模板，页面与模型不能提交任意URL、PromQL或SQL。

### 身份与归属

- GPU唯一键为`(cluster,node,device_uuid)`；归一UUID别名，冲突、跨节点歧义及MIG分区不能冒充完整整卡。
- HAMi业务身份使用`namespace_name/pod_name/container_name`，不能取exporter自身的标签代替。
- 业务归属先匹配数据库中的有效精确绑定，再应用管理员目录规则；未匹配或同优先级冲突保留未知。目录反映当前配置，不回写历史归属。
- 多个业务可关联同一GPU，关联卡数不能相加作为物理总数，整卡使用量不分摊给各模型。配置中存在但未被观测的业务不计作正在运行或零占用。
- 普通容器实际使用须匹配KSM当前Pod UID、节点与运行时容器ID；名称相同不代表同一生命周期。

### 指标定义

| 指标 | 语义与限制 |
| --- | --- |
| `hami_memory_size` | 虚拟显存容量，设备去重后汇总 |
| `hami_container_vmemory_allocated` | 容器虚拟显存额度；未分配=同设备容量−已分配，不代表物理空闲或可调度 |
| `DCGM_FI_DEV_GPU_UTIL` | 整卡计算利用率0–100%，与分配额度无必然对应关系 |
| `DCGM_FI_DEV_FB_USED/FREE` | 物理显存，原始MiB；独立使用接口可换算为bytes |
| `DCGM_FI_DEV_GPU_TEMP` | 摄氏度；阈值仅产生运营关注 |
| `DCGM_FI_DEV_XID_ERRORS` | 最近XID编号，不是错误次数或本次新增故障 |
| `DCGM_FI_DEV_ECC_DBE_VOL_TOTAL` | 驱动周期累计双位ECC，不代表本次增量 |
| 主机CPU / 系统内存 / load1 | 近5分钟idle rate、`MemTotal−MemAvailable`、运行队列负载；集群CPU按逻辑核数加权 |
| 容器CPU / 内存 | cAdvisor近5分钟rate，单位核；内存是working set，不是显存或申请量 |
| 容器requests/limits | KSM声明，严格核验CPU/core和memory/byte；未报告不补零，也不推定无限 |
| Ready / 启动 / 重启 | 健康与生命周期证据；Running不能识别训练、加载、检查点或等待输入 |

保留原始值与单位：MB=10⁶ bytes、GB=10⁹ bytes、MiB=2²⁰ bytes，页面仅提供MB/GB切换。未知单位不换算；只有明确确认的成功空记录才可补零，查询错误、NaN、缺测和部分结果不能补零。

GPU“未使用”计数仅按当前物理显存原始值**精确为0**，很小的正值和缺测都不算零。清单不完整时不提供完整合计，占用核查保留微小非零利用率的精度。

主机范围限已核验GPU节点，DMI只保存获准型号，不保存序列号；挂载点和网卡分别展示，不任意求和。K8s allocatable不是当前可调度承诺。普通容器最多500行，含未申请GPU的容器，但不是全量集群负载；声明合计也不等于包含init/overhead的Pod有效调度需求。当前普通容器仅存最新快照，尚无其长历史或通用Agent工具。

源端定义参考：[DCGM计数器](https://github.com/NVIDIA/dcgm-exporter/blob/main/etc/default-counters.csv)、[KSM Pod](https://github.com/kubernetes/kube-state-metrics/blob/main/docs/metrics/workload/pod-metrics.md)、[cAdvisor](https://github.com/google/cadvisor/blob/master/docs/storage/prometheus.md)。本项目实际接入以固定模板代码为准。

## 3. 存储、同步与历史质量

### Schema与表分组

当前为**schema15**；[schema.sql](../backend/app/history/schema.sql)是早期引导结构，完整库由[编号迁移](../backend/app/history/migrations)生成。迁移先校验模式、来源、单位与补零契约，再在维护锁和事务中执行；可重跑，失败回滚，保留已有事实。不能单改版本号降级。

| 表组 | 用途 |
| --- | --- |
| `history_metadata`、`resource_snapshot` | 数据契约、版本及每集群最新快照/有限期last_good |
| `history_entity`、`history_sample`、`history_coverage` | 额度多维实体、唯一时间网格及覆盖 |
| `history_rollup`、进度/来源/补洞状态表 | 充分统计、断点、持久化源端起点及共享冷却 |
| `resource_device`、实际使用桶/覆盖表 | 累计GPU身份与实际利用率、物理显存等历史 |
| `resource_business_model`、`resource_model_binding` | 模型归属与有效区间，同一身份最多一个未关闭绑定 |
| `operations_metric_snapshot`、`node_metric_snapshot`、`workload_resource_snapshot` | GPU指标、主机、普通容器最新观测 |
| `host_metric_bucket`、`host_history_coverage` | 主机区间统计与覆盖，不伪造GPU UUID |
| `host_history_point`、`host_point_coverage` | 独立小时主机时点与回填检查点 |
| `efficiency_*_sample`、`efficiency_coverage` | 近期整卡、业务/容器及生命周期使用证据 |
| `investigation_task/event/feedback`、`agent_task_memory` | 调查、证据、追加反馈及私有对象/任务上下文 |
| `operations_record/decision/issue/issue_event` | 冻结规划/报告、追加复核、问题去重及版本流转 |
| `product_event`、`product_analytics_metadata` | UUID去重的匿名事件、时间索引和首次采集时间 |

已废弃写入口对应的历史调查表仍保留，避免丢失旧记录。累计设备登记不能当作当前卡数。相同实体/粒度/时间幂等写入；失败重查不把旧可信值覆盖成缺测，也不冒充本次新数据。

### 粒度与保留

页面范围为近1小时、1天、1周、1个月、3个月和全部，月范围按上海自然月。额度趋势1h/1d/1w使用分钟/5分钟/5分钟，其余使用小时；实际GPU/主机历史1h/1d/1w使用分钟/5分钟/小时。显示步长为存储粒度整倍数，每序列最多721点，尾部预留至少120秒采集延迟。

| 数据 | 保留策略 |
| --- | --- |
| 额度分钟 / 5分钟 | 约2天 / 8天，删除前固化完整小时桶统计 |
| 额度小时采样及归档 | 保留全部已发现历史，不按四个月自动删除 |
| GPU实际使用、主机分钟 / 5分钟 / 小时 | 约2天 / 8天 / 四个自然月，先聚合再清理 |
| 独立占用/容器使用事实 | 2天；统一调查记录90天 |
| 规划、运营交付与问题 | 当前长期保留 |
| 产品事件 | 90天，接收事件时每小时惰性清理 |
| 最新快照 | 按集群/实体覆盖更新，不每刷新一次新增一份 |

每条样本仅有一个粒度，但同一时刻可以有不同粒度的独立记录，不能跨粒度或层级混加。归档保存sum/min/max/有效数/预期数/覆盖，均值按有效数加权；分配率保留逐点比率，不能用两个均值相除代替。分钟/5分钟固化小时，额度小时再固化上海自然日；清理与固化同事务，已过期的细粒度不能补造。

“全部”额度从持久化源端起点开始；各集群起点不同，未发现完成则保留状态，起点不能证明中间完整。主机“全部已存历史”和实际使用四个月保留窗口与之区分。

### 同步与查询

- 当前快照每轮完成后默认等30秒；额度历史循环等60秒，按粒度新网格刷新尾部，缺口及旧历史另有预算。
- 实际指标、主机、普通容器复用一分钟循环和共享锁；主机近期每轮最多30分钟，失败/空结果冷却10分钟。
- 主机长趋势可直接按小时网格回填到独立时点表；完整小时均值/极值仍需分钟原料，管理员可选aggregate策略。超时缩批，成功后逐步恢复，中断保留已提交批次。
- 历史Service只读库。GPU利用率是整卡时段均值的平均，CPU按核数加权，内存及负载按设备/节点求和；缺口不补零。
- 主机`auto`仅在各指标/集群有效点均不减少且至少一项增加时选择小时采样，返回`sampling=hourly_point`。时点值不是整小时均值/极值，CPU时点值仍是源端近5分钟rate，不能证明采样间无尖峰或持续低效。

工作台与资产默认每30秒读库，历史图每分钟读库；普通容器按需读取。生产刷新不触发源端，开发兼容路径受持久化冷却、合并及API限流约束。

原始资源默认超过120秒过期；主机、固定指标、普通容器各用180秒时效。部分失败不抹去其他有效指标，过期/last_good不进入当前完整合计。API区分读库、求值、采集和入库时间，不宣称跨Service的原子快照。贡献分析只比较同粒度、足够覆盖的窗口，Top K保留全量计数和截断状态。

## 4. Agent、规划与运营

### 执行与证据

资源助手先在本地解析明确请求，复杂问题可由模型将公开词汇投影组合为查询目标。简单当前计数不调用模型；综合配置读取GPU节点快照；变化、覆盖和占用问题进入共用[InvestigationRuntime](../backend/app/agents/runtime.py)，不复制多套循环。

```text
目标与范围 → 模型选择只读工具 → Service取证 → 假设与反例核验
                  ↑                  ↓
                  └── 证据不足且仍有预算 ─┘
                          ↓
                事实 / 解释 / 未知 → 回答与记录
```

[ResourceRegistry](../backend/app/agents/registry.py)组合原变化诊断与使用工具，提供匿名快照、多资源趋势、历史覆盖、同步状态、业务下钻及`assess_hypothesis`。变化调查复核分子/分母及Node→Namespace→Pod贡献；没有源端覆盖证据时，不能把本地缺口归因于Prometheus丢失。

[Verifier](../backend/app/agents/verification.py)保留稳定引用、范围/内容指纹、单位、实际时间、粒度和覆盖。区间统计缺口与小时采样缺口分开；不同指标/实体/窗口不能直接互为反证。未知单位、跨范围引用、贡献冲突阻止确定归因。数值与状态由服务端形成，模型自由文本不作为测量事实。

模型只获公开目标、匿名引用和必要统计，不获原始问题、私有绑定或Namespace/Pod/IP/UUID。问题与手选范围冲突会拒绝；绝对日期/未支持的时长引导专业页，具名对象未解析时要求从本地实体中选择。领域内自由提问仍受已有工具和数据覆盖限制，不是任意问题均能回答。

### 预算、流式与记忆

- 模型/工具次数、超时、共享并发2及单轮最多3个工具共同约束；批量响应最多解析32项，额外请求明确未执行，不能扩大执行预算。无必要证据直接结束时最多给一次计入预算的修正机会。
- 通过真实SSE读取模型Markdown，逐段检查事实占位符后用NDJSON返回；数值、型号和引用由已查证事实展开。生成最多25秒，理解和回答计入总轮次/超时。
- 失败、截断、无效引用、取消时清除未完成草稿并保留事实回退。页面默认折叠核对事实、证据及步骤，不渲染外部图片/链接或原始HTML。
- 任务ID与UUID幂等键避免重试重复执行；保存阶段、证据、覆盖和终态。继续生成新子任务，重新取证，继承/收窄集群及GPU/节点对象，多个候选的“它”需要选择。
- [任务记忆](../backend/app/agents/memory.py)保存目标、相对窗口、假设、已查工具、待办及私有对象绑定；来源/单位/授权契约改变不能串用。根任务行原子预留预算，最多4轮，含澄清、失败和取消。
- 相同幂等ID返回原冻结结果并标记已保存；旧失败/取消只能提供上下文，不能复用未完成结论。进程重启不自动恢复，也不是向量检索记忆或企业多租户会话。

### 使用核查与确定性决策

占用核查筛选观察末点存在分配、整卡平均利用率不高于输入上限、覆盖至少90%且末点有效的GPU。当前额度与资源明细共用快照，历史末点额度另列；均值和峰值不依赖可选生命周期信号。

深入调查核对DCGM、HAMi容器SM/显存/kernel及KSM启动/重启/UID反例。容器SM仅在精确型号、历史可信标志和当前允许清单均验证后使用；空清单不能形成任务级低使用结论。均值低不等于持续低效，更不能据此计算可回收额度；长窗口小时趋势不能替代1小时/1天分钟证据。

部署评估默认输入GPU数量及每卡显存，高级条件折叠；逐卡比较`capacity−allocated`，按节点约束生成额度组合，用有效历史最低额度提示风险。运行时长支持小时/天/周/月，月换算30天，只记录需求，不参与排序、预测或扩大窗口。缺少完整配额、拓扑、亲和和预约证据，不能保证部署。

报告是人工触发、核对后导出的确定性汇总，不为汇总强制调用模型。本机工作区可冻结需求/结果和证据，复核追加不覆盖原记录；同ID不同内容409，问题按活动指纹去重并防版本冲突。上述持久化不是企业审批或资源写操作。规则关注项只使用已核验指标，不发外部通知，不重启、迁移或调度工作负载。

### 查询与任务一致性实测

2026-11-16本机只读实测：两集群当前观测36张GPU、157个容器，数据库约1.35GB。7类查询（资源汇总、容器快照、单卡1小时/1天/1周/1个月/3个月历史），分别以1和4并发各执行20次，共280次，错误0，外部请求0。4并发资源汇总p95为22.41ms，单卡3个月历史p95为27.72ms。由`validate-production.py --runs 20 --concurrency 4`复现；这是已有数据上的服务层短测，不含HTTP、模型或持续生产负载，也不证明历史无缺口。

`benchmark_agent_tasks.py`在独立Mock测试库使用合成工作器：20个同ID并发请求仅执行1次，其余19个收到执行中拒绝；完成后20次回放不增加执行，任务/证据各保留1条。另核验同ID不同请求拒绝、取消后部分证据保留及迟到完成不能改写取消终态。不是实际模型调用、跨进程崩溃恢复或exactly-once保证。脱敏原始报告保存在本机`.local/validation/showcase-value-20261116.json`，演示PDF从报告提取数值。

### 对照评测

[冻结数据集](../backend/app/agents/fixtures/benchmark_v1.json)含24个合成任务，开发16/留出8，覆盖变化、未知单位、贡献冲突、统计与采样缺口、整卡活动。规则读取全部固定模板；Single-shot读取相同证据调用一次模型；Agent自主选工具后走核验，不启用生产确定性补查。

[试测轨迹](../backend/tests/fixtures/agent-smoke-20261106.json)保留失败与修复后结果；所有真实DeepSeek试测均为合成数据：

| 批次 | 规则 | 单次模型原始输出 | Agent + Verifier |

## 5. 使用统计、接口与安全

### 匿名使用统计

入口`#settings?view=usage`，与进程内接口p95遥测分开。访问事件仅含页面/功能枚举、事件ID、随机浏览器UUID；服务端哈希浏览器标识并使用接收时间，不记录IP、UA、原始URL、问题或业务标签。批次最多10事件/4KB，有界缓存、幂等重试和卸载尽力发送不阻塞业务，不保证无损。

PV记录首次打开与规范化页面切换，筛选/范围/自动刷新不额外记PV，StrictMode不重复首屏。UV按窗口去重，DAU按上海自然日去重，不把DAU求和当UV或把浏览器数当实名人数。存储受限使用内存标识，清除标识、多设备、离线或拦截会影响计数；启用前的日期显示未采集。

关键操作包括查询、诊断、核查、评估、报告生成/导出、历史切换和手动刷新；次数是触发尝试，含失败，不代表所有点击或成功执行。Agent复用非旧版导入任务，按创建时间/任务ID统计；继续是新任务，幂等回放不是。完整完成率为`complete/非running任务`，受限、澄清、拒绝、失败、取消及中断不算完整成功；平均耗时取有结束时间的任务，含失败/取消。LLM调用已知数与未知数分开，无样本显示未知；完整完成率不是结论正确率。

## 6. 当前限制与后续

已实现监控、数据库历史、多资源扩展、调查闭环、流式助手、规划/运营及匿名统计。未完成的企业认证、权限、TLS/网络隔离、备份恢复演练、真实业务正确性及持续负载仍需部署环境验收，不能用本机短测替代。
